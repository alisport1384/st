# ۰۳ · معماری اپ اندروید

## ۱) ماژول‌ها
| ماژول | نوع | وابستگی | نقش |
|---|---|---|---|
| `:engine` | کتابخانهٔ JVM خالص | هیچ | استراتژی، کارگزار کاغذی، گزارش، ذخیره‌سازی |
| `:cli` | اجرایی JVM | `:engine` | بک‌تست خط فرمان روی CSV (صحت‌سنجی مستقل از گوشی) |
| `:app` | اندروید (minSdk 24، target 34) | `:engine` | رابط، چارت، فید، سرویس لایو، لاگر، هشدار |

`:engine` هیچ `import android.*` ندارد. به همین دلیل تست‌های الگوریتمی سریع‌اند و همان کد روی
سرور/خط فرمان هم اجرا می‌شود.

## ۲) نمای کلاس‌های اپ
```
MainActivity  ── نمایش ۵ تب، تمام‌صفحه، دیالوگ‌ها، منوی زمینه، بنر هشدار
 ├─ AppState.instance           (Singleton، منبع یکتای حقیقت)
 │   ├─ candles: ArrayList<Candle>        کندل‌های تریگر۲ (چارت)
 │   ├─ engine: Engine                     موتور استراتژی
 │   ├─ broker: PaperBroker                کارگزار کاغذی
 │   ├─ cfg: EngineCfg                     پارامترها
 │   ├─ io: Executor                       کارهای پس‌زمینه
 │   └─ wireLogging()                      جفت‌سازی لاگر/هشدار با موتور
 ├─ ui/ChartView                 چارت کندل + نواحی + ژست‌ها + SetupOverlay
 ├─ ui/EquityChartView           منحنی سرمایه (تب گزارش)
 ├─ data/Feed                    Yahoo / gold-api / Swissquote / CoinGecko + CSV
 ├─ data/Storage                 فایل gz داخلی، SAF (انتخاب مسیر)، گزارش
 ├─ svc/EngineService            سرویس پیش‌زمینهٔ ارزیابی زنده (نوتیفیکیشن دائمی)
 ├─ util/Log                     لاگر (md + txt) + دنبالهٔ نشست قبلی در خروجی
 ├─ util/Alerts                  هشدار + نوتیفیکیشن + تاریخچه + مهار نرخ
 ├─ util/AnrWatchdog             سگ نگهبان نخ رابط (پشتهٔ نخ اصلی هنگام فریز)
 ├─ util/CoalescingGate          دروازهٔ «حداکثر یک تیک لایو در جریان»
 ├─ util/Ui , Palette , Fa       ابزار UI، رنگ‌ها، اعداد فارسی، `Fa.short` (مهار طول رشته)
```

## ۳) چرخهٔ عمر
```
onCreate : UI → AppState.init(ctx) → بارگذاری خودکار وضعیت → راه‌اندازی نما
onResume : updateLiveBadge ، بازآوری PollFg (اگر سرویس روشن باشد)
onPause  : توقف PollFg ، ذخیرهٔ خودکار (اگر روشن باشد)
onDestroy: Log.i پایان نشست ، flush
BACK     : اگر تمام‌صفحه → خروج از تمام‌صفحه؛ وگرنه خروج از تب
```
`AppState.init(ctx)` کارهای زیر را انجام می‌دهد:
1. `Log.init(ctx, "1.3.5")` (خواندن تنظیمات لاگر از SharedPreferences با کلید `log_enabled`، پیش‌فرض **خاموش**)
2. `Alerts.init(ctx)` (کانال نوتیفیکیشن `goldpin_alerts_v1`)
3. خواندن `auto_fullscreen` (پیش‌فرض **خاموش**؛ مهاجرت نسخهٔ ۱٫۱ هم یک‌بار آن را خاموش می‌کند)
4. `wireLogging()` → وصل کردن `engine.logSink`، `broker.logSink`، `engine.alertSink`، `broker.alertSink`

## ۴) جریان داده (بک‌تست و لایو)
```
[دانلود تاریخچه]  Feed.downloadBase()  →  کندل‌های پایه M1
        │
        ▼
  AppState.setCandles()  →  Agg (تجمیع به تایم‌فریم چارت)  →  Engine.feed()
        │                                                      │
        │                                   barCommitHook ────► PaperBroker.onBar()
        ▼
   ChartView.refresh()  ◄── notifyUi()  ◄── listener ها

[لایو]  EngineService (هر livePollMs، روی HandlerThread اختصاصی)
        →  CoalescingGate.tryAcquire()   ← تیک تکراری حذف می‌شود، در صف نمی‌ایستد
        →  net.execute { Feed.yahooChart() + Feed.spotPrice() }      ← شبکه روی نخ جدا
        →  io.execute { AppState.feedLiveTail(tail) }
                 ├─ mergeTail()          ← گارد تایم‌فریم؛ در صورت ناهم‌خوانی جایگزینی سری
                 ├─ اگر کندل بستهٔ جدید > ۳ ⇒ inBacktest=true (بازپخش ساکت)
                 └─ Engine.feed() → PaperBroker.onBar() → publishSnapshot()
        →  main.post { notifyUi() }  ← فقط یک بار در هر تیک
        →  Alerts.fire (با مهار نرخ) + Log (ثبت)
```

## ۵) قلاب‌های موتور → اپ
| قلاب | نوع | چه‌وقت صدا زده می‌شود |
|---|---|---|
| `engine.barCommitHook` | `(Candle)->Unit` | پایان پردازش هر کندل بستهٔ تریگر۲ |
| `engine.logSink` | `(cat,msg,data)->Unit` | هر رخداد قابل‌ثبت موتور |
| `engine.alertSink` | `(kind,title,body)->Unit` | هر رخداد هشداردهنده |
| `broker.logSink` / `broker.alertSink` | همان | سفارش‌ها، پر شدن‌ها، پله‌های خروج |
`wireLogging()` اگر لاگر خاموش باشد قلاب‌های لاگ را `null` می‌کند ⇒ **هزینهٔ صفر** وقتی خاموش است.

## ۶) نخ‌بندی (Threading)
| کار | نخ |
|---|---|
| اجرای موتور (دانلود/بازسازی/لایو) | `AppState.io` — **هرگز نخ UI** (از ۱٫۳٫۱) |
| دانلود تاریخچه | `AppState.io` → نتیجه با `main.post` به UI |
| درخواست شبکهٔ لایو | `net` (اجراکنندهٔ جدا) ⇒ socket معطل، کارهای `io` را گروگان نمی‌گیرد (از ۱٫۳٫۲) |
| تغییر وضعیت لایو | `AppState.io` زیر `stateLock` ⇒ با `rebuild()` هم‌زمان نمی‌شود |
| حلقهٔ تیک لایو | `HandlerThread` اختصاصی `goldpin-live-tick` — **از ۱٫۳٫۵ نه `Looper` اصلی** |
| نوشتن لاگ | نخ نویسندهٔ اختصاصی؛ `Log.add()` فقط در صف می‌گذارد (از ۱٫۳٫۲) |
| ذخیرهٔ خودکار | `AppState.io` (gzip یک وضعیت چندمگابایتی روی نخ UI = ANR) |
| رابط کاربری | فقط `notifyUi()`/`refreshCurrent()` با ضد‌سیل ۳۰۰ms |

هیچ کار سنگینی و هیچ عملیات شبکه‌ای روی نخ UI نیست. دو استثنای تاریخ‌ساز که پیدا و
رفع شدند در `13_CHANGELOG_FA.md` (۱٫۳٫۱ تا ۱٫۳٫۵) مستند شده‌اند؛ خلاصهٔ درس:
**حجم کار مهم است، نه فقط تعداد کارها** — یک رشتهٔ یک‌مگابایتی در یک `TextView`
به‌تنهایی کافی است.

### ۶٫۱) دروازهٔ تیک لایو (`CoalescingGate`) — از ۱٫۳٫۲
پیش‌تر صف اجراکنندهٔ تک‌رشته‌ای **بی‌پایان** بود و تیک‌ها حتی وقتی تیک قبلی تمام نشده
بود در صف می‌نشستند؛ با فید کند، صف رشد می‌کرد و چون ذخیره/بازسازی/خروجی لاگ هم به
همان صف می‌روند، کل اپ «فریز» می‌شد. حالا یک تیک لایو در هر لحظه در جریان است و تیک
اضافی **حذف** می‌شود (`lastLiveSkips`)، به‌علاوهٔ fixed-delay و عقب‌گرد نمایی تا ۵ دقیقه.

| اندازه‌گیری (`LiveBackpressureTest`، تیک ۳۰ms / فاصلهٔ ۴ms) | بدون دروازه (۱٫۳٫۱) | با دروازه (۱٫۳٫۲) |
|---|---|---|
| تیک ارسال‌شده | ۵۷ | ۵۷ تلاش → ۷ اجرا |
| عمق صف هنگام فشردن دکمه | **۴۸** | **۱** |
| تأخیر عمل رابط کاربری | **۱۴۸۵ms** | **۴ms** |

### ۶٫۲) سگ نگهبان نخ رابط (`AnrWatchdog`) — از ۱٫۳٫۳
یک نخ پس‌زمینه هر `700ms` یک کار سبک روی `Looper` اصلی می‌گذارد؛ اگر `2500ms` اجرا
نشد یعنی نخ رابط مسدود است و **پشتهٔ نخ اصلی** در لاگ `ANR` ثبت و `flush` می‌شود.
جزئیات در `06_LOGGER_FA.md` §۳٫۱.

## ۸) قواعد معماری (نباید نقض شوند)
1. `:engine` نباید به اندروید وابسته شود.
2. هیچ کتابخانهٔ بیرونی اضافه نشود (نه AndroidX، نه Gson، نه MPAndroidChart).
3. هر رخداد مهم موتور باید هم لاگ و هم (در صورت هشدار بودن) alert بدهد.
4. هر تغییر رفتار = یک ورودی در `13_CHANGELOG_FA.md`.
5. مقدار پیش‌فرض هر قابلیت «محافظه‌کارانه» است (لاگر خاموش، هشدار خاموش، مخصوصاً در بک‌تست).
6. **هیچ رشتهٔ بی‌مهار به `View` نمی‌رسد.** پیام خطای کتابخانه‌ها می‌تواند صدها هزار
   نویسه باشد؛ هر چه به `TextView`/`Toast` می‌رود باید از `Fa.short(...)` رد شود.
   (این قاعده مستقیماً از فریز ۱٫۳٫۵ بیرون آمد.)
7. **هیچ حلقهٔ تکرارشونده‌ای روی `Looper` اصلی زمان‌بندی نمی‌شود** مگر کار نمایشی خالص.
8. هر ادعای «فریز رفع شد» باید با **ردپا یا اندازه‌گیری** پشتیبانی شود، نه با استدلال.
