# ۰۶ · لاگر (Log)

## ۱) اصول
* **پیش‌فرض: خاموش.** تا کاربر در «تنظیمات → لاگر» روشن نکند، هیچ خطی ثبت نمی‌شود و موتور
  هیچ متنی نمی‌سازد (قلاب‌ها `null` می‌شوند).
* **دو خروجی هم‌زمان**: `<نام>.md` (برای خواندن و اشتراک‌گذاری) و `<نام>.txt` (برای ارسال به پشتیبانی).
* امن برای اجرای طولانی: چرخش فایل پس از ۱٫۵ مگابایت، بافر حافظه محدود به ۶۰۰۰ خط، هیچ‌گاه اپ را کرش نمی‌کند.

## ۲) محل فایل‌ها
```
<Android/data/com.alisport.goldpin/files/logs/
     goldpin_log_20261008_123406.md
     goldpin_log_20261008_123406.txt
     goldpin_log_20261008_123406_p2.md     ← در صورت گذشتن از ۱٫۵MB
```
* از داخل اپ: «تنظیمات → لاگر → اشتراک‌گذاری md / txt» (کد درخواست ۱۰۵ و ۱۰۶).
* روی گوشی: مسیر بالا در حافظهٔ داخلی برنامه؛ با هیچ ابزار خارجی لازم نیست کار کنید.

## ۳) دسته‌ها (Categories)
| دسته | چه چیزی ثبت می‌شود |
|---|---|
| `APP` | چرخهٔ عمر، راه‌اندازی، پاک‌سازی، تنظیمات عمومی |
| `ENGINE` | کندل مهم، Ready، روند، ساخت ناحیه، هر مرحلهٔ ستاپ |
| `ZONE` | ساخت/رد/حذف باکس ناحیه و دلیل آن |
| `ORDER` | ثبت سفارش لیمیت، تمدید، پر شدن، لغو، منقضی شدن |
| `TRADE` | ورود، پله‌های خروج، حدضرر، حدسود، سر‌به‌سر، پایان معامله |
| `FEED` | دانلود تاریخچه، پاسخ Yahoo، قیمت لحظه‌ای، ورود CSV، ساخت حجم تقریبی |
| `STORE` | ذخیره/بازیابی وضعیت و گزارش‌ها + اندازهٔ فایل |
| `LIVE` | سرویس ارزیابی زنده: شروع/توقف، هر به‌روزرسانی، ذخیرهٔ دوره‌ای |
| `ALERT` | تغییر تنظیمات هشدار و ارسال هشدار |
| `UI` | تب‌ها، تمام‌صفحه، منو، ژست‌ها |
| `CFG` | تغییر هر پارامتر (مود تایم‌فریمی، تایم‌فریم چارت، پارامترهای موتور) |
| `PERF` | زمان‌بندی عملیات سنگین (بک‌تست، تجمیع، دانلود) |
| `ANR` | **فریز نخ رابط**: پشتهٔ نخ اصلی در لحظهٔ مسدودی (از ۱٫۳٫۳) |

هر دسته در تنظیمات لاگر **جداگانه** قابل خاموش/روشن است (`Log.setMuted(ctx, cat, true)`).

## ۳٫۱) سگ نگهبان نخ رابط (`AnrWatchdog`) — از ۱٫۳٫۳
هر `700ms` یک کار سبک روی `Looper` اصلی گذاشته می‌شود؛ اگر `2500ms` اجرا نشد یعنی نخ
رابط مسدود است و **پشتهٔ نخ اصلی** با دستهٔ `ANR` و سطح `ERROR` ثبت و بلافاصله
`Log.flush()` می‌شود — حتی اگر فریز ادامه پیدا کند. برای یک فریز تا ۳ ردپای پی‌گیرانه
گرفته می‌شود تا لاگ پر نشود.

```
ERROR [ANR] main thread stalled · lag=2500ms state=RUNNABLE detected=#1 worst=2500ms
  at android.graphics.text.LineBreaker.nComputeLineBreaks(Native Method)
  at android.text.StaticLayout.generate(StaticLayout.java:784)
  at android.widget.TextView.makeSingleLayout(TextView.java:10181)
```

این ابزار همان چیزی است که ریشهٔ فریز لایو را در ۱٫۳٫۵ لو داد؛ پیش از آن سه حدس
پشت‌سرهم اشتباه بود، چون در لحظهٔ فریز «نمی‌شد لاگ گرفت».

| شمارنده | معنی |
|---|---|
| `AnrWatchdog.detectedCount` | چند بار فریز تشخیص داده شده |
| `AnrWatchdog.worstStallMs` | طولانی‌ترین فریز ثبت‌شده |
| `AnrWatchdog.thresholdMs` / `checkMs` | آستانهٔ اعلام / فاصلهٔ نمونه‌برداری |

## ۳٫۲) دنبالهٔ نشست قبلی در خروجی — از ۱٫۳٫۴
`exportLog` فقط بافر حافظهٔ **نشست جاری** را می‌داد؛ یعنی اگر اپ فریز می‌کرد و بسته
می‌شد، ردپای `ANR` روی دیسک می‌ماند ولی بیرون نمی‌آمد. حالا `Log.init` آخرین
**۵۰۰ خط** تازه‌ترین فایل لاگ را نگه می‌دارد و `reportTxt()`/`reportMd()` آن را با
سرصفحهٔ مشخص به خروجی می‌چسبانند.

⚠ عمداً در `buffer` ریخته **نمی‌شود**؛ وگرنه در هر بازکردن اپ، خطوط نشست قبل دوباره
در فایل نشست جدید نوشته و تکرار می‌شدند.

**روش گرفتن لاگ بعد از فریز:** ۱) ۱۰–۱۵ ثانیه صبر کنید. ۲) اپ را ببندید.
۳) دوباره باز کنید و خروجی بگیرید.

## ۴) سطح‌ها
`VERBOSE(0) < DEBUG(1) < INFO(2) < WARN(3) < ERROR(4)` — خطوطی با سطح کمتر از حد انتخاب‌شده ثبت نمی‌شوند.
* VERBOSE → جزئیات داغ حلقه‌ها (فقط برای عیب‌یابی عمیق)
* DEBUG → هر کندل لایو، جزئیات فید
* INFO → رخدادهای مهم (پیش‌فرض)
* WARN → خطاهای بازیافت‌شدنی
* ERROR → خطاها با متن استثنا

## ۵) قالب خروجی
فایل `.md` با سرصفحه و جدول:
```markdown
# گزارش لاگ GoldPin
نسخه اپ: ۱٫۱ — تاریخ: ۱۴۰۵/۰۷/۱۶ — دستگاه: samsung SM-A125F — اندروید ۱۳

| زمان | سطح | دسته | پیام | داده |
|---|---|---|---|---|
| 12:34:06.412 | INFO | ENGINE | کندل مهم Ready BU (pinBU) تایید شد | lo=4123.50 hi=4128.90 bar=1244 |
```
فایل `.txt` همان خطوط با قالب ستونی:
```
12:34:06.412  INFO   [ENGINE]  کندل مهم Ready BU (pinBU) تایید شد · lo=4123.50 hi=4128.90 bar=1244
```

## ۶) API عمومی
```kotlin
Log.init(ctx, "1.3.5")               // از AppState.initApp
Log.setEnabled(ctx, true)            // روشن/خاموش (در SharedPreferences: log_enabled)
Log.setLevel(ctx, Log.INFO)          // سطح
Log.setWriteToFile(ctx, true)        // نوشتن روی فایل
Log.setLogcat(ctx, true)             // آینه در logcat
Log.setMuted(ctx, Log.CAT_LIVE, true)// خاموش‌کردن یک دسته
Log.i(Log.CAT_ENGINE, "پیام", "داده")          // i/d/w/v/e
Log.e(Log.CAT_FEED, "پیام", throwable)        // ثبت استثنا
Log.tail(300)                        // آخرین خطوط برای نمایش در اپ
Log.reportMd() / Log.reportTxt()     // گزارش کامل نشست
Log.files() / Log.dirPath()          // فایل‌ها و مسیر
Log.flush() / Log.closeSession()
```

## ۷) اتصال به موتور (مهم)
`AppState.wireLogging()`:
```kotlin
engine.logSink  = { cat, msg, data -> Log.i(cat, msg, data) }   // اگر روشن باشد
broker.logSink  = { cat, msg, data -> Log.i(cat, msg, data) }
else → null          // خاموش = بدون هیچ هزینه
```
نقاط اتصال در اپ: فید (دانلود، قیمت لحظه‌ای)، ذخیره‌سازی (فایل/SAF/گزارش)، سرویس لایو (شروع/توقف/تپش/ذخیرهٔ
دوره‌ای)، UI (تب، تمام‌صفحه)، چرخهٔ عمر، تغییر تنظیمات.

## ۸) کارایی (اندازه‌گیری‌شده)
روی بک‌تست کامل **۱۸۲٬۷۴۷ کندل**: بدون سینک ۸۸۶ms، با سینک ۸۹۳ms ⇒ **سرباره ≈ ۷ms (۱٫۰۱×)**
و نتیجهٔ بک‌تست (۲۵۵ سفارش/۲۵۵ معامله) **عیناً یکسان**. تعداد خطوط تولیدشده ≈ ۲۲٬۸۰۰ خط در هر اجرای کامل
(به‌همین دلیل چرخش ۱٫۵ مگابایتی لازم است). این آزمون در `LogPerfTest` قفل شده است.

## ۹) در بازیابی و ذخیره
مسیر لاگ در فایل وضعیت **ذخیره نمی‌شود** (وابسته به دستگاه است). تنظیمات لاگر در `SharedPreferences`
با کلیدهای `log_enabled`، `log_level`، `log_to_file`، `log_logcat`، `log_muted` نگهداری می‌شوند.
