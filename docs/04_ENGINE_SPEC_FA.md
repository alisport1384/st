## ۳) جریان پردازش

```
feed(req, loader)          ← ورودی اصلی (از اپ یا cli)
   └─ process(candles, lastIsClosed)
        برای هر کندل:
            اگر بسته:  processClosed(cd)
            اگر زنده:  updateLive(cd)
```

### `processClosed` — ترتیب ثابت و غیرقابل تغییر

```
۱. aggS.step(...)        →  structureEngine(cd)   ← ساختار: کندل مهم، روند
۲. aggM.step(...)        →  middleEngine(cd)      ← تایید میانی
۳. agg1.step(...)        →  trigger1Engine(cd)    ← کندل ولوم کم
۴.                           trigger2Engine(cd)    ← کندل ولوم زیاد و مسلح شدن
۵.                       broker.onBar(cd)          ← پر شدن، حد ضرر/سود
۶.                       onCandle?.invoke(aggS.cur)
```

### `updateLive` — **هیچ حالتی را تغییر نمی‌دهد**

فقط یک اسنپ‌شات برای نمایش می‌سازد. این تنها راهِ نگه‌داشتن پاسخگویی رابط
کاربری در حالت زنده است: قیمت زنده هرگز استراتژی را جلو نمی‌برد.

## ۴) تایم‌فریم‌ها

`aggS` ساختار، `aggM` میانی، `agg1` تریگر یک — هر کدام یک `Agg` مستقل با
`step()` و `barDur()` خودشان. تریگر دو روی **کندل چارت** اجرا می‌شود، نه یک تایم‌فریم تجمیع‌شده.

**⚠ `Agg.step` اولین کندل کامل هر تایم‌فریم را دور می‌ریزد** (`periods >= 2`). اختلاف ۷-۳.

## ۶) کارگزاری کاغذی

```
registerLimit(s, cd)      ثبت سفارش لیمیت (⚠ حداکثر یک سفارش — اختلاف ۷-۱)
onBar(cd)                 پر شدن → انقضا → manageBar → refreshEquity
cancel / cancelAll        (⚠ هنوز closeAll دارد — اختلاف ۷-۲)
onSetupInvalidated        فقط سفارش PENDING را برمی‌دارد، معاملهٔ باز دست نمی‌خورد
restorePending            بازیابی سفارش باز از ذخیره‌سازی
addExit                   pnl خام — بدون کارمزد (⚠ اختلاف ۷-۴)
```

**خروجی سفارش:** `FILLED · TP1 · TP2 · TPX · SL · CANCELLED_EXPIRED`
**حالت سفارش:** `PENDING · OPEN · CLOSED · CANCELLED`

## ۷) اسنپ‌شات

`Snapshot` وضعیت کامل موتور است. `UiSnapshot` لایهٔ رابط کاربری.

**⚠ مسئلهٔ شناخته‌شده:** `refreshCurrent()` در اپ، `s.engine.trend` و `s.broker.equity`
را **بیرون** از `UiSnapshot` می‌خواند. اگر این مقادیر در اسنپ‌شات نبود، باید اضافه
شوند — نه این‌که از بیرون خوانده شوند.
